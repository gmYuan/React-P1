### 步骤 1:完善 childFibers，实现多节点 DOM Diff

**路径:** `packages/react-reconciler/src/childFibers.ts`

**修改内容:**
1. 新增 `ExistingChildren` 类型别名，表示 key/index → FiberNode 的 Map
2. 新增 `reconcileChildrenArray`，实现多节点 diff 核心逻辑：将旧兄弟链存入 Map，遍历新子节点数组，通过 `updateFromMap` 判断是否可复用，并根据 `lastPlacedIndex` 标记移动（`Placement`）或插入，最后将 Map 中未被复用的旧节点全部标记删除

## 第三部分:主要知识点

### 1. 多节点 Diff 需要支持的操作

与单节点相比，多节点在原有插入（`Placement`）、删除（`ChildDeletion`）的基础上，新增了**移动**操作，移动同样复用 `Placement` flag 表示。

| 场景 | 单节点 | 多节点 |
|---|---|---|
| 插入 | Placement | Placement |
| 删除 | ChildDeletion | ChildDeletion |
| 移动 | — | Placement |

---

### 2. 整体 Diff 流程（4 步）

1. **将 current 中所有同级 Fiber 保存在 Map 中**，key 为 Fiber 的 `key`（有则用 key，无则用 index 字符串）
2. **遍历 newChild 数组**，对每个 element 查 Map 判断是否可复用，存在两种情况：
   - a. Map 中存在对应 current fiber，且可以复用
   - b. Map 中不存在对应 current fiber，或不能复用
3. **判断是插入还是移动**（见下方步骤 3 详解）
4. **遍历结束后，Map 中剩余的节点全部标记删除**

---

### 3. 步骤 2 详解：是否可复用

首先根据 key 从 Map 中获取 current fiber，如果不存在 current fiber，则没有复用的可能。

存在 current fiber 时，分情况讨论：

- **element 是 HostText**：current fiber 的 tag 也是 `HostText` → 可复用，调用 `useFiber`；否则不可复用，创建新节点
- **element 是 ReactElement**：current fiber 的 `type` 与 element 的 `type` 相同 → 可复用，调用 `useFiber`；否则不可复用，创建新节点
- **TODO：element 是数组或 Fragment**：对应如下场景，当前尚未实现

```jsx
// 数组子节点
<ul>
  <li/>
  <li/>
  {[<li/>, <li/>]}   // ← 这个 element 本身是数组
</ul>

// Fragment 子节点（等价写法）
<ul>
  <li/>
  <li/>
  <>
    <li/>
    <li/>
  </>
</ul>
```

---

### 4. 步骤 3 详解：插入 / 移动判断

「移动」具体是指**向右移动**。

**判断依据**：比较 element 的新 index 与其对应 current fiber 的旧 index。

以 `A1 B2 C3 → B2 C3 A1` 为例（数字表示旧 index）：

| element | 新 index | 旧 index | 是否移动 |
|---|---|---|---|
| B | 0 | 1 | 否（1 ≥ lastPlacedIndex=0，更新 lastPlacedIndex=1） |
| C | 1 | 2 | 否（2 ≥ lastPlacedIndex=1，更新 lastPlacedIndex=2） |
| A | 2 | 0 | 是（0 < lastPlacedIndex=2，标记 Placement） |

核心规则：遍历时维护 `lastPlacedIndex`（最后一个不需要移动的 fiber 在 current 中的 index）：
- 可复用 fiber 的旧 index **≥** `lastPlacedIndex` → **不移动**，更新 `lastPlacedIndex`
- 可复用 fiber 的旧 index **<** `lastPlacedIndex` → **标记移动**（`Placement`）
- 无法复用（mount 新节点）→ **标记插入**（`Placement`）

---

### 5. 移动操作的执行

`Placement` 同时对应两种操作：**移动**和**插入**。

- **插入**：之前用 `parentNode.appendChild` 即可
- **移动**：需要额外支持 `parentNode.insertBefore`，在目标节点之前插入

`insertBefore` 需要找到「目标兄弟 Host 节点」，有两点注意：

1. **目标兄弟不一定是 Fiber 的直接兄弟节点**，因为中间可能隔着 FunctionComponent 等非 Host 类型节点：

```jsx
// 情况1：<A/> 的兄弟 Host 节点是 B 内部的 <div/>，而不是 <B/> 本身
<A/><B/>
function B() { return <div/>; }

// 情况2：<App/> 的兄弟 Host 节点是 <div/>，但 App 内部的 <A/> 的兄弟 Host 节点是 <div/>
<App/><div/>
function App() { return <A/>; }
```

2. **不稳定的 Host 节点**（自身带有 `Placement` flag）不能作为目标兄弟 Host 节点

---

### 6. 当前实现的不足

- 不支持数组类型的子节点（`{[<li/>, <li/>]}`）
- 不支持 Fragment（`<>...</>`）
