### 步骤 1:新增 `react-noop-renderer` 的 Rollup 打包配置

**路径:** `scripts/rollup/react-noop-renderer.config.js`

**修改内容:**
1. 新增 `react-noop-renderer` 的独立 Rollup 配置文件，接入 `getPackageJSON/resolvePkgPath/getBaseRollupPlugins` 工具链
2. 配置 UMD 产物输出为 `dist/index.js`，全局名为 `ReactNoopRenderer`
3. 配置 `external` 为 `peerDependencies + scheduler`，避免把调度器打进 bundle
4. 配置 `alias(hostConfig)` 指向 `react-noop-renderer/src/hostConfig.ts`，确保 reconciler 在打包时命中 Noop 宿主实现
5. 配置 `rollup-plugin-generate-package-json`，自动生成 `dist/package.json`
6. 调整 TypeScript `exclude` 路径为 `packages/react-dom/**/*`，修正路径匹配写法

**关键代码:**

```diff
+ // scripts/rollup/react-noop-renderer.config.js
+ import { getPackageJSON, resolvePkgPath, getBaseRollupPlugins } from './utils';
+ import generatePackageJson from 'rollup-plugin-generate-package-json';
+ import alias from '@rollup/plugin-alias';
+
+ const { name, module, peerDependencies } = getPackageJSON(
+   'react-noop-renderer'
+ );
+
+ export default [
+   {
+     input: `${pkgPath}/${module}`,
+     output: [
+       {
+         file: `${pkgDistPath}/index.js`,
+         name: 'ReactNoopRenderer',
+         format: 'umd'
+       }
+     ],
+     external: [...Object.keys(peerDependencies), 'scheduler'],
+     plugins: [
+       ...getBaseRollupPlugins({
+         typescript: {
+           exclude: ['packages/react-dom/**/*'],
+           tsconfigOverride: {
+             compilerOptions: {
+               paths: {
+                 hostConfig: [`./${name}/src/hostConfig.ts`]
+               }
+             }
+           }
+         }
+       }),
+       alias({
+         entries: {
+           hostConfig: `${pkgPath}/src/hostConfig.ts`
+         }
+       }),
+       generatePackageJson({
+         inputFolder: pkgPath,
+         outputFolder: pkgDistPath
+       })
+     ]
+   }
+ ];
```

## 第四部分:个人 Q&A

### 1. 这批改动整体在做什么？为什么要改这些文件？

**核心目标：让 `react-noop-renderer` 能够正确打包和运行**

之前已经实现了 `react-noop-renderer`（一个测试用的渲染器，不操作真实 DOM，而是生成纯 JS 对象），但它还不能被正确编译和使用。这批改动分为两部分：

**主线任务：补全打包配置**

1. **创建打包配置文件**（`react-noop-renderer.config.js`）
   - 项目用 Rollup 来打包代码，之前只有 `react.config.js` 和 `react-dom.config.js`
   - 需要给 `react-noop-renderer` 创建独立的打包配置，告诉 Rollup 如何编译它
   - 关键配置：`hostConfig` 路径映射，让 React 核心代码在打包 noop-renderer 时使用测试环境的节点操作，而不是浏览器 DOM 操作

2. **接入构建流程**（`dev.config.js`）
   - 虽然写了配置，但 dev 构建入口没有引用它
   - 把 noop-renderer 加到构建列表里，让 `npm run build:dev` 时能同时生成它的产物

3. **规范依赖边界**（`react-dom.config.js` 和 `react-noop-renderer.config.js`）
   - 把 `scheduler` 标记为 `external`（外部依赖）
   - 避免 scheduler 代码被重复打包到 react-dom 和 react-noop-renderer 里
   - 让运行时环境（Vite/Jest/Node.js）从统一的 `node_modules/scheduler` 加载，而不是每个包都内置一份

**副线任务：修复代码 bug**

4. **修复类型问题**（`completeWork.ts`）
   - `appendAllChildren` 函数的 `parent` 参数类型过窄，只支持根容器
   - 实际使用中，普通节点（如 `<div>`）也需要作为父节点挂载子节点
   - 扩展类型为 `Container | Instance`，让函数支持两种场景

5. **修复空指针问题**（`fiber.ts`）
   - 调试字段 `__ygmIsWIP` 的赋值没有判空
   - 首次渲染时某些 Fiber 的 `alternate` 为 `null`，直接访问会崩溃
   - 加上空值判断，避免边界情况下的运行时错误

**为什么现在才发现这些 bug？**

在实现和测试 noop-renderer 时，触发了一些之前没有遇到的代码路径和类型检查，暴露了这些潜在问题。noop-renderer 的类型定义更严格（Container 和 Instance 是不同的对象结构），所以类型问题更容易被发现。

### 2. 把 scheduler 标记为 external 是什么意思？它是怎么工作的？

**external 的作用：告诉打包工具"不要把这个依赖的代码打包进来"**

#### 不标记 external 会怎样？

如果不标记，Rollup 打包时会：

```javascript
// 源码：react-reconciler/src/workLoop.ts
import { unstable_scheduleCallback } from 'scheduler';

// Rollup 打包时：
// 1. 去 node_modules 找到 scheduler 包
// 2. 把 scheduler 的全部代码复制一份
// 3. 和 react-dom 的代码合并成一个文件

// 最终生成：dist/react-dom/index.js（包含 scheduler + react-dom）
```

**问题：**
- `react-dom` 打包时会复制一份 scheduler 代码（假设 3000 行）
- `react-noop-renderer` 打包时又会复制一份 scheduler 代码（又 3000 行）
- 如果同时使用两个包，浏览器会加载两份相同的 scheduler 代码，浪费流量和内存

#### 标记 external 后呢？

```javascript
// Rollup 配置
external: [...Object.keys(peerDependencies), 'scheduler']

// Rollup 打包时：
// 1. 看到 scheduler 在 external 列表里
// 2. 不复制 scheduler 的代码
// 3. 在生成的文件里保留 import 语句

// 最终生成：dist/react-dom/index.js（只有 react-dom 代码）
// 文件里会有：require('scheduler') 或 import 'scheduler'
```

打包后的代码大概是这样：

```javascript
// dist/react-dom/index.js（UMD 格式）
(function (global, factory) {
  typeof exports === 'object' 
    ? factory(exports, require('scheduler'))  // ← 这里只是"引用"，不包含代码
    : ...
})(this, function (exports, scheduler) {
  // 使用 scheduler.unstable_scheduleCallback
});
```

#### 运行时谁来提供 scheduler？

关键点：虽然打包时不包含 scheduler 代码，但**根目录的 `package.json` 安装了 scheduler**：

```json
"dependencies": {
  "scheduler": "0.23.0"
}
```

所以 `node_modules/scheduler` 是存在的。运行时根据环境不同，有不同的处理方式：

**情况 1：开发时（Vite）**

```javascript
// demos/test-fc/main.tsx
import ReactDOM from 'react-noop-renderer';
```

执行流程：
1. Vite 加载 `dist/react-noop-renderer/index.js`
2. 发现里面有 `import 'scheduler'`
3. Vite 去 `node_modules/scheduler` 找到这个包并加载
4. 打包给浏览器时，scheduler 只有一份

**情况 2：测试时（Jest）**

```javascript
// 测试文件
const ReactNoop = require('react-noop-renderer');
```

执行流程：
1. Jest 加载 `dist/react-noop-renderer/index.js`
2. 遇到 `require('scheduler')`
3. Node.js 的 require 机制去 `node_modules/scheduler` 找到并加载

**情况 3：直接在浏览器用（不常见）**

如果直接在 HTML 里用 `<script>` 标签，需要手动先加载 scheduler：

```html
<script src="node_modules/scheduler/umd/scheduler.production.min.js"></script>
<script src="dist/react-noop-renderer/index.js"></script>
```

#### 总结

- **打包时**：Rollup 看到 `external: ['scheduler']`，不把 scheduler 代码打进 bundle
- **开发/测试时**：Vite/Jest 看到 `import 'scheduler'`，从 `node_modules` 加载
- **最终效果**：scheduler 代码只有一份，被 react-dom 和 react-noop-renderer 共享，避免重复打包
