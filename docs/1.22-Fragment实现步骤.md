## 第三部分:主要知识点

为了提高组件结构灵活性，需要实现 Fragment。具体来说，需要区分以下几种情况：

---

### 1. Fragment 包裹其他组件（作为根节点）

```html
<>
  <div></div>
  <div></div>
</>

// 对应DOM
<div></div>
<div></div>
```

这种情况的 JSX 转换结果：

```js
jsxs(Fragment, {
  children: [
    jsx("div", {}),
    jsx("div", {})
  ]
});
```

type 为 `Fragment` 的 ReactElement，对**单一节点的 Diff** 需要考虑 Fragment 的情况。

---

### 2. Fragment 与其他组件同级

```html
<ul>
  <>
    <li>1</li>
    <li>2</li>
  </>
  <li>3</li>
  <li>4</li>
</ul>

// 对应DOM
<ul>
  <li>1</li>
  <li>2</li>
  <li>3</li>
  <li>4</li>
</ul>
```

这种情况的 JSX 转换结果：

```js
jsxs('ul', {
  children: [
    jsxs(Fragment, {
      children: [
        jsx('li', { children: '1' }),
        jsx('li', { children: '2' })
      ]
    }),
    jsx('li', { children: '3' }),
    jsx('li', { children: '4' })
  ]
});
```

`children` 为数组类型，则进入 `reconcileChildrenArray` 方法，数组中的某一项为 Fragment，所以需要增加「type 为 Fragment 的 ReactElement 的判断」，同时 `beginWork` 中需要增加 Fragment 类型的判断。

---

### 3. 数组形式的 Fragment

```html
// arr = [<li>c</li>, <li>d</li>]

<ul>
  <li>a</li>
  <li>b</li>
  {arr}
</ul>

// 对应DOM
<ul>
  <li>a</li>
  <li>b</li>
  <li>c</li>
  <li>d</li>
</ul>
```

这种情况的 JSX 转换结果：

```js
jsxs('ul', {
  children: [
    jsx('li', { children: 'a' }),
    jsx('li', { children: 'b' }),
    arr
  ]
});
```

`children` 为数组类型，则进入 `reconcileChildrenArray` 方法，数组中的某一项本身还是数组，所以需要增加「`reconcileChildrenArray` 中数组类型的判断」。

---

### 4. Fragment 对 ChildDeletion 的影响

`ChildDeletion` 删除 DOM 的逻辑：

1. 找到子树的根 Host 节点
2. 找到子树对应的父级 Host 节点
3. 从父级 Host 节点中删除子树根 Host 节点

考虑删除普通节点（如 `<p>`）的情况：

```html
<div>
  <p>xxx</p>
</div>
```

子树根 Host 节点只有一个（`<p>`），直接 `removeChild` 即可。

考虑删除 Fragment 后，子树的根 Host 节点**可能存在多个**：

```html
<div>
  <>
    <p>xxx</p>
    <p>yyy</p>
  </>
</div>
```

Fragment 本身不产生 DOM，删除它时需要删除其所有子 Host 节点（`<p>xxx</p>` 和 `<p>yyy</p>`），所以原来用单个 `rootHostNode` 记录的方式需要改为**数组**收集所有根 Host 节点，再逐个 `removeChild`。

---

### 5. 对 React 包的影响

React 包需要导出 `Fragment`，用于 JSX 转换时引入 Fragment 类型。
