## 第四部分:个人 Q&A

### 1. 这些文件改动，通俗易懂地说主要做了什么事情？

**整体目标：让你的 React 项目能够跑单元测试**

你现在手写了一个迷你版 React（叫 `react-noop-renderer`），之前只能在浏览器里运行看效果。但是写测试的时候就麻烦了，因为测试环境没配好。这次改动就是**把测试环境搭建起来**。

---

#### 具体做了什么？分成 4 件事：

**1️⃣ 解决代码规范问题**（步骤 1）

**问题：** Jest 配置文件用的是老式的 `require()` 语法，但你的 ESLint 不允许用 `require`，会报红线警告。

**解决：** 在 `.eslintrc.json` 里把这条规则关掉（`"@typescript-eslint/no-var-requires": "off"`），让配置文件可以安心用 `require`。

**类比：** 就像你在写作业时用了简写，老师说"不能用简写"，你就跟老师说"配置文件可以用简写吧"。

---

**2️⃣ 安装测试工具包**（步骤 2）

**问题：** 你要测试 React 组件，但 Jest 默认不认识 React，需要额外的工具。

**解决：** 安装了 `jest-react` 这个包（像装了一个"React 测试助手"），它会自动帮你处理 React 组件的测试。

**类比：** 你想测试一辆车能不能跑，光有测试场地（Jest）不够，还得装个"汽车测试仪"（jest-react）。

---

**3️⃣ 配置测试环境的"规则"**（步骤 3）

这是**核心改动**，做了 3 件关键的事：

**3.1 Mock 掉 scheduler（调度器）**

```javascript
moduleNameMapper: {
  '^scheduler$': '<rootDir>/node_modules/scheduler/unstable_mock.js'
}
```

**问题：** React 内部用 `scheduler` 来控制任务优先级（比如先渲染重要的，后渲染不重要的）。但测试时不能真的等它慢慢调度，测试会跑不完。

**解决：** 用一个**假的 scheduler**（mock 版本），让测试可以手动控制"现在该执行哪个任务了"。

**类比：** 真实世界里，外卖小哥会按"距离远近"送餐。测试时改成"你点一下按钮，小哥就立刻送到"，这样测试才能快速验证结果。

---

**3.2 开启 Fake Timers（假定时器）**

```javascript
fakeTimers: {
  enableGlobally: true,
  legacyFakeTimers: true
}
```

**问题：** 你的 React 代码里可能有 `setTimeout(() => { ... }, 1000)`（延迟 1 秒执行）。如果测试真的等 1 秒，跑一个测试就要等半天。

**解决：** 用**假的时钟**，你可以在测试里直接"快进时间"，比如 `jest.advanceTimersByTime(1000)` 就能跳过 1 秒。

**类比：** 真实世界里你要等红绿灯 60 秒。测试时你可以直接"时间快进"，瞬间变绿灯。

---

**3.3 添加测试初始化脚本**

```javascript
setupFilesAfterEnv: ['./scripts/jest/setupJest.js']
```

**问题：** 测试之前需要做一些准备工作（比如全局配置、自定义断言等）。

**解决：** 告诉 Jest："每次跑测试前，先执行这个 `setupJest.js` 文件，把环境准备好"。

**类比：** 你去健身房前，先换运动服、热身，这个脚本就是"自动帮你做准备"。

---

**4️⃣ 暴露 Scheduler 给测试代码**（步骤 4）

```typescript
return {
  _Scheduler: Scheduler,  // ← 新增这行
  render(element) { ... }
}
```

**问题：** 测试代码需要手动控制 React 的调度（比如"现在执行优先级高的任务"），但之前拿不到 `Scheduler` 对象。

**解决：** 在 `createRoot()` 返回的对象里，加一个 `_Scheduler` 字段，让测试代码能直接访问。

**类比：** 你买了个遥控车，但遥控器被锁在盒子里。现在把遥控器拿出来（`_Scheduler`），你就能手动控制车了。

---

#### 用实际例子总结一下

改完之后，你可以写这样的测试：

```javascript
test('React 优先渲染高优先级任务', () => {
  const root = createRoot();
  
  // 渲染一个组件
  root.render(<App />);
  
  // 手动控制调度器，执行任务
  root._Scheduler.unstable_flushAllWithoutAsserting();
  
  // 快进时间 1 秒
  jest.advanceTimersByTime(1000);
  
  // 验证结果
  expect(root.getChildrenAsJSX()).toEqual(<div>Hello</div>);
});
```

**之前不行，因为：**
- 没有 `jest-react`，不知道怎么测 React
- `scheduler` 是真的，测试会卡住
- `setTimeout` 是真的，要真等时间
- 拿不到 `_Scheduler`，无法手动控制

**现在可以了，因为：**
- ✅ 安装了 `jest-react`
- ✅ 用 mock 版 scheduler，可以手动触发
- ✅ 用假时钟，可以快进时间
- ✅ 暴露了 `_Scheduler`，测试代码能操控

---

#### 一句话总结

**这次改动就是：把 Jest 测试环境从"不能测 React"升级成"可以完全控制 React 的调度和时间"，让你能写自动化测试来验证 React 的各种功能。**
