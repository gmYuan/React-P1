# React 点击更新函数调用栈（main2.tsx 最新版）

基于 `demos/test-fc/main2.tsx` 最新代码：

- 点击按钮 `Start low-priority render` 触发 `DefaultLane` 更新（并发、可中断）
- 点击 `<ul>` 触发 `SyncLane` 更新（高优先级、同步）

本文聚焦这两个交互在一次调试中的典型链路：  
**先触发低优先级渲染，再用高优先级点击打断它**。

---

## 完整调用栈

```text
前置状态（交互前）：
- App 已挂载，num = 100
- App 上存在两个 useEffect（`[]` 与 `[num]`）
- Child 渲染开销较大（每个 Child busy-wait），便于观察并发中断
- 页面上有两个交互入口：
  1) `button.onClick -> startLowPriorityRender()`
  2) `ul.onClick -> updateNum(50)`

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【A 路径】先触发低优先级更新（DefaultLane）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. 点击 button 触发 startLowPriorityRender()
   └─ onClick 回调执行：unstable_runWithPriority(NormalPriority, fn)
      └─ fn 内连续触发两次更新：
         ├─ updateNum(300)
         └─ setTick(v => v + 1)

2. dispatchSetState（以 updateNum(300) 为例）
   └─ dispatchSetState(fiber, queue, action)                     // fiberHooks.ts
      ├─ requestUpdateLanes()                                    // fiberLanes.ts
      │  ├─ unstable_getCurrentPriorityLevel() = NormalPriority
      │  └─ schedulerPriorityToLane() -> DefaultLane
      ├─ createUpdate(action=300, lane=DefaultLane)
      ├─ enqueueUpdate(queue, update)
      └─ scheduleUpdateOnFiber(fiber, DefaultLane)               // workLoop.ts

3. 调度 DefaultLane 并发任务
   └─ ensureRootIsScheduled(root)
      ├─ getHighestPriorityLane(root.pendingLanes) = DefaultLane
      ├─ laneToSchedulerPriority(DefaultLane) -> NormalPriority
      └─ scheduleCallback(NormalPriority, performConcurrentWorkOnRoot.bind(null, root))

4. 宏任务中执行并发 render
   └─ performConcurrentWorkOnRoot(root)
      ├─ flushPassiveEffects(...)                                // 先清 effect
      ├─ updateLane = getHighestPriorityLane(...) = DefaultLane
      ├─ needSync = false
      └─ renderRoot(root, DefaultLane, true)                     // shouldTimeSlice=true
         └─ workLoopConcurrent()
            └─ while (workInProgress !== null && !unstable_shouldYield())
               └─ performUnitOfWork(...)

5. 低优先级 render 可能被切片中断
   └─ 若 shouldYield 为 true 且 workInProgress 仍非空
      ├─ renderRoot 返回 RootIncomplete
      └─ performConcurrentWorkOnRoot 返回 continuation（继续执行函数）

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【B 路径】低优先级进行中，点击 ul 触发高优先级更新（SyncLane）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

6. 浏览器 click 事件触发（目标 ul/li）
   └─ dispatchEvent(container, 'click', e)                       // SyntheticEvent.ts
      ├─ collectPaths(...)
      ├─ createSyntheticEvent(e)
      └─ triggerEventFlow(bubble, syntheticEvent)
         └─ unstable_runWithPriority(ImmediatePriority, callback)
            └─ callback 内执行 updateNum(50)

7. dispatchSetState(updateNum(50))
   └─ requestUpdateLanes()
      ├─ unstable_getCurrentPriorityLevel() = ImmediatePriority
      └─ schedulerPriorityToLane() -> SyncLane
   └─ enqueueUpdate(... SyncLane)
   └─ scheduleUpdateOnFiber(fiber, SyncLane)

8. 更高优先级插队重排调度
   └─ ensureRootIsScheduled(root)
      ├─ curPriority = SyncLane，prevPriority = DefaultLane
      ├─ 若 existingCallback 存在 -> unstable_cancelCallback(existingCallback)
      ├─ scheduleSyncCallback(performSyncWorkOnRoot.bind(null, root))
      └─ scheduleMicroTask(flushSyncCallback)

9. 在途并发任务感知被抢占并退出
   └─ performConcurrentWorkOnRoot(root) 的后续切片中：
      ├─ if (root.callbackNode !== curCallback) return null
      └─ 低优先级 continuation 不再继续推进

10. 微任务立即执行同步更新
    └─ flushSyncCallback()
       └─ performSyncWorkOnRoot(root)
          ├─ nextLane = getHighestPriorityLane(root.pendingLanes) = SyncLane
          ├─ renderRoot(root, SyncLane, false)                   // shouldTimeSlice=false
          └─ commitRoot(root)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【SyncLane render/commit 细节】以 num 最终更新到 50 为例
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

11. beginWork(HostRoot)
    └─ updateHostRoot(...)
       ├─ processUpdateQueue(baseState, pending, SyncLane)
       └─ reconcileChildren(...)

12. beginWork(App) -> renderWithHooks
    ├─ useState(num) 处理队列，得到新值 50
    ├─ useState(tick) 处理队列（若有 pending）
    ├─ useEffect([])：依赖不变，不触发
    └─ useEffect([num])：依赖变化，标记 PassiveEffect

13. beginWork(ul) -> reconcileChildrenArray
    ├─ 新 children 是 50 个 Child（0..49）
    ├─ 旧列表里 0..49 复用
    └─ 旧列表剩余 50..299（或 50..99，取决于前序 commit）标记删除

14. completeWork 自底向上冒泡 flags
    └─ HostRoot 汇总出 ChildDeletion / PassiveEffect 等副作用标记

15. commitRoot
    ├─ commitMutationEffects(...)
    │  ├─ 处理 ChildDeletion -> commitDeletion -> removeChild(...)
    │  └─ 处理 PassiveEffect -> collect 到 pendingPassiveEffects.update
    ├─ root.current = finishedWork
    └─ scheduleCallback(NormalPriority, flushPassiveEffects)

16. flushPassiveEffects（异步）
    ├─ 先 destroy：`AppEft2 destroy num = 上一次值`
    ├─ 再 create：`AppEft2 change num = 50`
    └─ flushSyncCallback()（处理 effect 内可能再次触发的同步更新）

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【仅点击 ul 的简化路径】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

17. 若不先点 button，仅点 ul
    ├─ 直接走 ImmediatePriority -> SyncLane
    ├─ 进入 performSyncWorkOnRoot（无并发中断过程）
    └─ 本质是一次普通同步更新
```

---

## 关键点总结

1. **button 更新是 DefaultLane**：通过 `runWithPriority(NormalPriority)` 主动制造低优先级并发渲染。  
2. **ul 点击更新是 SyncLane**：click 事件映射 `ImmediatePriority -> SyncLane`，会抢占低优先级任务。  
3. **抢占关键点**：`ensureRootIsScheduled` 会取消旧 callback，并在并发任务中通过 `root.callbackNode !== curCallback` 让旧任务退出。  
4. **高优先级落地路径**：`flushSyncCallback -> performSyncWorkOnRoot -> renderRoot(..., false) -> commitRoot`。  
5. **effect 时序不变**：`[num]` 仍是 commit 后异步执行，先 destroy 再 create；`[]` 依赖不变不重复触发。
