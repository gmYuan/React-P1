### 步骤 1:集成 Scheduler 优先级到 fiberLanes 模块，建立 Lane 与 Scheduler 优先级的双向映射

**路径:** `packages/react-reconciler/src/fiberLanes.ts`

**修改内容:**
1. 新增 Scheduler 优先级常量导入（`unstable_ImmediatePriority`、`unstable_UserBlockingPriority`、`unstable_NormalPriority`、`unstable_IdlePriority`），为后续优先级转换提供依赖
2. 新增 `unstable_getCurrentPriorityLevel` 导入，用于在更新时获取当前 Scheduler 上下文的优先级
3. 扩展 Lane 优先级体系，新增 `InputContinuousLane`（用户连续输入）、`DefaultLane`（默认优先级）、`IdlePriority`（空闲优先级），与原有的 `SyncLane` 共同构成完整的 Lane 优先级模型

## 第三部分:主要知识点

### 本次改动的核心内容

#### 做了什么事

本次改动是**建立 React 内部 Lane 模型与 Scheduler 优先级系统的双向桥接**，让两个优先级体系能够互相转换和协同工作。

具体包括两个关键模块：

1. **`fiberLanes.ts`** - 扩展 Lane 优先级模型，增加优先级转换函数
2. **`SyntheticEvent.ts`** - 启用事件系统的优先级调度机制

---

### 为什么要改动

结合课程截图中的理论，改动的动机是：

#### 1. React 和 Scheduler 使用不同的优先级体系

课程指出：
- **运行流程在 React 时，使用的是 Lane 模型**
- **运行流程在 Scheduler 时，使用的是优先级（5种优先级）**

所以需要在两者之间建立转换桥梁。

#### 2. 优先级从何而来

根据课程"扩展交互"部分：
> **答案：不同交互对应不同优先级**

可以根据"触发更新的上下文环境"赋予不同优先级，比如：
- **点击事件需要同步处理** → `ImmediatePriority`
- **滚动事件优先级再低点** → `UserBlockingPriority`
- **useEffect create 回调中触发更新的优先级** → 较低优先级

#### 3. 优先级如何影响更新

课程明确指出：
> **只要优先级能影响 update，就能影响更新**

当前掌握的与优先级相关的信息包括：
- Scheduler 的 5 种优先级
- React 中的 Lane 模型

---

### 实现了什么功能

#### 功能 1：优先级双向转换机制

**新增了两个核心函数：**

```typescript
// Lane → Scheduler 优先级
laneToSchedulerPriority(lanes: number): number

// Scheduler 优先级 → Lane
schedulerPriorityToLane(schedulerPriority: number): number
```

**映射关系：**

| Lane 模型 | Scheduler 优先级 | 使用场景 |
|----------|----------------|---------|
| `SyncLane` (0b0001) | `ImmediatePriority` | 点击、键盘输入等需要立即响应 |
| `InputContinuousLane` (0b0010) | `UserBlockingPriority` | 滚动等用户连续交互 |
| `DefaultLane` (0b0100) | `NormalPriority` | 普通更新 |
| `IdleLane` (0b1000) | `IdlePriority` | 空闲时执行 |

---

#### 功能 2：事件触发时自动设置优先级上下文

**改造前：**
```typescript
// 直接执行回调，没有优先级概念
callback.call(null, syntheticEvent);
```

**改造后：**
```typescript
// 使用 Scheduler 的 runWithPriority 包裹执行
unstable_runWithPriority(
  eventTypeToSchedulerPriority(syntheticEvent.type),
  () => {
    callback.call(null, syntheticEvent);
  }
);
```

**事件类型到优先级的映射：**
- `click` / `keydown` / `keyup` → `ImmediatePriority`（最高优先级，同步执行）
- `scroll` → `UserBlockingPriority`（用户阻塞优先级）
- 其他事件 → `NormalPriority`（普通优先级）

---

#### 功能 3：requestUpdateLanes 从上下文获取优先级

**改造前：**
```typescript
export function requestUpdateLanes() {
  return SyncLane;  // 所有更新都是同步优先级
}
```

**改造后：**
```typescript
export function requestUpdateLanes() {
  // 从 Scheduler 上下文读取当前优先级
  const currentSchedulerPriority = unstable_getCurrentPriorityLevel();
  // 转换为 Lane
  const lane = schedulerPriorityToLane(currentSchedulerPriority);
  return lane;
}
```

### 完整工作流程

结合课程中的理论，现在的完整流程是：

```
用户点击按钮
  ↓
事件系统捕获 click 事件
  ↓
SyntheticEvent.ts: eventTypeToSchedulerPriority('click') 
  → 返回 ImmediatePriority
  ↓

  ↓

  ↓

  → 调用 unstable_getCurrentPriorityLevel() 
  → 得到 ImmediatePriority
  ↓

  → 转换为 SyncLane
  ↓

  ↓

  ↓

  → 转换回 ImmediatePriority
  ↓
scheduleCallback(ImmediatePriority, performWork)
  ↓
Scheduler 按优先级执行更新
```

### 核心价值

这次改动实现了课程中提到的关键能力：

1. **让不同交互产生不同优先级** - 通过事件类型映射实现
2. **让优先级能够影响 update** - 通过 Lane 转换实现
3. **打通 React 和 Scheduler 两个体系** - 通过双向转换函数实现

这是实现并发更新的基础设施，为后续的"时间切片"和"高优先级打断低优先级"提供了优先级能力支持。

### Q1: 完整工作流程是否正确？`laneToSchedulerPriority` 什么时候会被调用？

#### 原始流程描述的问题

最初描述的流程：

```
用户点击按钮
  ↓
事件系统捕获 click 事件
  ↓
SyntheticEvent.ts: eventTypeToSchedulerPriority('click') 
  → 返回 ImmediatePriority
  ↓
使用 unstable_runWithPriority(ImmediatePriority, callback)
设置 Scheduler 优先级上下文
  ↓
callback 内部触发 setState
  ↓
fiberLanes.ts: requestUpdateLanes()
  → 调用 unstable_getCurrentPriorityLevel() 
  → 得到 ImmediatePriority
  ↓
schedulerPriorityToLane(ImmediatePriority) 
  → 转换为 SyncLane
  ↓
update 对象携带 lane: SyncLane
  ↓
进入调度阶段，需要调用 Scheduler
  ↓
laneToSchedulerPriority(SyncLane) 
  → 转换回 ImmediatePriority
  ↓
scheduleCallback(ImmediatePriority, performWork)
  ↓
Scheduler 按优先级执行更新
```

**问题所在：最后三步不准确！**

#### 实际情况

根据 `workLoop.ts` 的 `ensureRootIsScheduled` 函数：

```typescript
function ensureRootIsScheduled(root: FiberRootNode) {
  const maxPendingLane = getHighestPriorityLane(root.pendingLanes);

  if (maxPendingLane === NoLane) {
    return;
  }

  if (maxPendingLane === SyncLane) {
    // 同步优先级，用微任务调度
    scheduleSyncCallback(performSyncWorkOnRoot.bind(null, root, maxPendingLane));
    scheduleMicroTask(flushSyncCallback);
  } else {
    // 其他优先级，用宏任务调度
    // 这里才会调用 laneToSchedulerPriority（目前还未实现）
  }
}
```

**关键发现：**
- **`SyncLane` 使用微任务调度，不经过 Scheduler，不调用 `laneToSchedulerPriority`**
- **只有非同步优先级才会调用 `laneToSchedulerPriority` 并通过 `scheduleCallback` 调度**

#### `laneToSchedulerPriority` 的触发时机

查看参考项目 `my-react-main-2xiao` 的实现：

```typescript
function ensureRootIsScheduled(root: FiberRootNode) {
  // ...
  if (updateLane === SyncLane) {
    // 同步优先级，用微任务调度
    scheduleSyncCallback(performSyncWorkOnRoot.bind(null, root));
    scheduleMicroTask(flushSyncCallback);
  } else {
    // 其他优先级，用宏任务调度
    const schedulerPriority = laneToSchedulerPriority(updateLane);  // ← 这里调用！
    newCallbackNode = scheduleCallback(
      schedulerPriority,
      performConcurrentWorkOnRoot.bind(null, root)
    );
  }
}
```

**触发条件：**
1. 更新的 `lane` 不是 `SyncLane`
2. 需要通过 Scheduler 进行并发调度时
3. 具体包括：`InputContinuousLane`、`DefaultLane`、`IdleLane` 等

#### 修正后的完整流程

应该根据不同优先级分为两条路径：

**路径 1：点击事件（同步优先级 - 不调用 `laneToSchedulerPriority`）**

```
用户点击按钮
  ↓
事件系统捕获 click 事件
  ↓
eventTypeToSchedulerPriority('click') → ImmediatePriority
  ↓
unstable_runWithPriority(ImmediatePriority, callback)
设置 Scheduler 优先级上下文
  ↓
callback 内部触发 setState
  ↓
requestUpdateLanes()
  → unstable_getCurrentPriorityLevel() → ImmediatePriority
  → schedulerPriorityToLane(ImmediatePriority) → SyncLane
  ↓
update 对象携带 lane: SyncLane
  ↓
ensureRootIsScheduled: 判断 lane === SyncLane
  ↓
使用微任务调度（不经过 Scheduler，不调用 laneToSchedulerPriority）
  ↓
scheduleSyncCallback(performSyncWorkOnRoot)
scheduleMicroTask(flushSyncCallback)
  ↓
微任务队列执行同步更新
```

**路径 2：滚动事件（并发优先级 - 调用 `laneToSchedulerPriority`）**

```
用户滚动页面
  ↓
事件系统捕获 scroll 事件
  ↓
eventTypeToSchedulerPriority('scroll') → UserBlockingPriority
  ↓
unstable_runWithPriority(UserBlockingPriority, callback)
设置 Scheduler 优先级上下文
  ↓
callback 内部触发 setState
  ↓
requestUpdateLanes()
  → unstable_getCurrentPriorityLevel() → UserBlockingPriority
  → schedulerPriorityToLane(UserBlockingPriority) → InputContinuousLane
  ↓
update 对象携带 lane: InputContinuousLane
  ↓
ensureRootIsScheduled: 判断 lane !== SyncLane，进入 else 分支
  ↓
laneToSchedulerPriority(InputContinuousLane)  ← 这里调用！
  → 转换回 UserBlockingPriority
  ↓
scheduleCallback(UserBlockingPriority, performConcurrentWorkOnRoot)
  ↓
Scheduler 按优先级执行并发更新（支持时间切片和中断）
```

#### 总结

1. **`SyncLane`（同步更新）**
   - 不调用 `laneToSchedulerPriority`
   - 使用微任务直接调度
   - 点击、键盘输入等高优先级事件走这条路径

2. **非 `SyncLane`（并发更新）**
   - 调用 `laneToSchedulerPriority` 将 Lane 转换为 Scheduler 优先级
   - 使用 `scheduleCallback` 通过 Scheduler 调度
   - 滚动、普通更新等走这条路径

3. **当前项目状态**
   - 本次改动只是添加了 `laneToSchedulerPriority` 函数定义
   - `ensureRootIsScheduled` 的 `else` 分支还未实现
   - 后续实现并发更新时才会真正调用这个函数
