### 🎯 第四阶段：Hooks 与 BaseQueue（核心）

#### 断点 8: UpdateState - 合并 BaseQueue ⭐

**文件:** `packages/react-reconciler/src/fiberHooks.ts`  
**行号:** 127  
**函数:** `updateState`

**代码:**
```typescript
if (baseQueue !== null) {
  // 合并 baseQueue 和 pending 链表
  const baseQueueFirst = baseQueue.next;
  const pendingFirst = pending.next;
  
  baseQueue.next = pendingFirst;
  pending.next = baseQueueFirst;
}
baseQueue = pending;
current.baseQueue = pending;  // 保存到 current
```

**观察内容:**

**第一次 render (IdleLane):**
- `baseQueue = null` → 跳过合并
- 直接处理 `pending = u2 -> u0 -> u1 -> u2`

**第二次 render (SyncLane):**
- `baseQueue = u1 -> u2` (从 current 恢复)
- `pending` 可能有新的 update
- 合并成一个链表后统一处理

**链表合并示例:**
```
假设:
  baseQueue: b2 -> b0 -> b1 -> b2
  pending:   p2 -> p0 -> p1 -> p2

合并后:
  b2 -> p0 -> p1 -> p2 -> b0 -> b1 -> b2
  (b2 的 next 指向 p0, p2 的 next 指向 b0)
```

**调试技巧:**
```javascript
// 在断点处查看 baseQueue
if (baseQueue) {
  console.log('--- BaseQueue 恢复 ---');
  let curr = baseQueue.next;
  let i = 0;
  do {
    console.log(`baseQueue[${i++}]:`, {
      lane: curr.lane.toString(2),
      action: curr.action
    });
    curr = curr.next;
  } while (curr !== baseQueue.next);
}
```

#### 断点 9: ProcessUpdateQueue - 优先级判断 ⭐⭐⭐

**文件:** `packages/react-reconciler/src/updateQueue.ts`  
**行号:** 95  
**函数:** `processUpdateQueue`

**代码:**
```typescript
if (!isSubsetOfLanes(renderLane, updateLane)) {
  // 优先级不够，跳过本次 Update
  const clone = createUpdate(pending.action, pending.lane);
  if (newBaseQueueLast === null) {
    // 第一个被跳过的
    newBaseQueueFirst = clone;
    newBaseQueueLast = clone;
    newBaseState = newState;  // 记录跳过前的 state
  } else {
    // 添加到链表
    newBaseQueueLast.next = clone;
    newBaseQueueLast = clone;
  }
} else {
  // 优先级足够
  if (newBaseQueueLast !== null) {
    // 前面有被跳过的，这个也要保存（保证连续性）
    const clone = createUpdate(pending.action, NoLane);
    newBaseQueueLast.next = clone;
    newBaseQueueLast = clone;
  }
  
  // 正常计算
  const action = pending.action;
  if (action instanceof Function) {
    newState = action(baseState);
  } else {
    newState = action;
  }
}
```

**这是整个 baseQueue 机制的核心！**

**第一次 render (renderLane = IdleLane = 0b1000):**

```
处理 u0:
  updateLane = 0b1000
  isSubsetOfLanes(0b1000, 0b1000) = true
  → 执行: newState = 0 + 1 = 1
  → newBaseQueueLast = null (还没有被跳过的)

处理 u1:
  updateLane = 0b0001 (SyncLane)
  isSubsetOfLanes(0b1000, 0b0001) = false ⭐
  → 跳过! 保存到 baseQueue
  → newBaseState = 1 (记录跳过前的 state)
  → newBaseQueueFirst = u1
  → newBaseQueueLast = u1

处理 u2:
  updateLane = 0b1000
  isSubsetOfLanes(0b1000, 0b1000) = true
  → 优先级够，但前面有被跳过的 (newBaseQueueLast !== null)
  → 执行: newState = 1 + 100 = 101
  → 也保存到 baseQueue (降级为 NoLane) ⭐
  → newBaseQueueLast.next = u2(NoLane)

返回:
  memoizedState = 101  (临时显示的值)
  baseState = 1        (最后没被跳过的结果)
  baseQueue = u1 -> u2(NoLane) -> u1
```

**第二次 render (renderLane = SyncLane = 0b0001):**

```
从 baseState = 1 开始
从 baseQueue = u1 -> u2(NoLane) 恢复

处理 u1:
  updateLane = 0b0001
  isSubsetOfLanes(0b0001, 0b0001) = true
  → 执行: newState = 10

处理 u2:
  updateLane = 0b0000 (NoLane，被降级的)
  isSubsetOfLanes(0b0001, 0b0000) = true (NoLane 总是包含)
  → 执行: newState = 10 + 100 = 110

返回:
  memoizedState = 110
  baseState = 110
  baseQueue = null (全部处理完)
```

### 🎯 第五阶段：Concurrent 工作流程

#### 断点 11: PerformConcurrentWorkOnRoot - 状态处理

**文件:** `packages/react-reconciler/src/workLoop.ts`  
**行号:** 约 280-300 行  
**函数:** `performConcurrentWorkOnRoot`

**代码:**
```typescript
const exitStatus = renderRoot(root, updateLane, !needSync);

if (exitStatus === RootIncomplete) {
  // 执行中断
  if (root.callbackNode !== curCallbackNode) {
    // 代表有更高优先级的任务插进来
    return null;
  }
  return performConcurrentWorkOnRoot.bind(null, root);
}

if (exitStatus === RootComplete) {
  // 执行完了
  const finishedWork = root.current.alternate;
  root.finishedWork = finishedWork;
  root.finishedLane = updateLane;
  wipRootRenderLane = NoLane;
  
  commitRoot(root);
}
```

**观察内容:**
- `RootIncomplete`: 时间切片中断或有更高优先级插入
- `RootComplete`: 渲染完成，进入 commit 阶段
- 返回自身 continuation 让 Scheduler 继续调度

## 常见问题

### Q1: 为什么 u2 参与计算了还要保存到 baseQueue？

**A**: 保证 update 的连续性。

如果不保存 u2：
```
第一次: 处理 u0, 跳过 u1, 处理 u2 → state = 101
第二次: 处理 u1 → state = 10
结果错误! u2 丢失了
```

如果保存 u2（降级 NoLane）：
```
第一次: 处理 u0, 跳过 u1, u2 保存 → state = 101 (临时)
第二次: 从 baseState=1, 处理 u1, 处理 u2 → state = 110
结果正确!
```

### Q2: 为什么要保存到 current.baseQueue？

**A**: 因为 render 可能被中断多次。

只要不进入 commit 阶段，current 和 wip 就不会互换，baseQueue 就能一直保存在 current 中，每次重新渲染都能从 current 恢复。

### Q3: baseState 和 memoizedState 有什么区别？

**A**:
- **baseState**: 本次更新参与计算的**初始** state（最后没被跳过的结果）
- **memoizedState**: 上次更新计算的**最终** state（考虑优先级的结果）

示例：
```
第一次 render:
  baseState = 0 (初始)
  处理后 memoizedState = 101 (临时结果)
  保存 newBaseState = 1 (u0 的结果)

第二次 render:
  baseState = 1 (从 newBaseState 开始)
  处理后 memoizedState = 110 (最终结果)
```

### Q4: 时间切片断点触发太频繁怎么办？

**A**: 使用条件断点。

在 `workLoopConcurrent` 的断点上右键 → Edit breakpoint：
```javascript
unstable_shouldYield() === true
```

这样只在中断时停下。

### Q5: 为什么 count 先显示 101 再变成 110？

**A**: 这是并发渲染的特性。

1. 第一次 render (IdleLane): 计算出 101（跳过了 u1）
2. commit 阶段: 页面显示 101
3. u1 触发高优先级 render (SyncLane)
4. 第二次 render: 从 baseState=1 重新计算，得到 110
5. commit 阶段: 页面更新为 110
