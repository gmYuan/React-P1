## 第二部分:实战步骤

### 步骤 1:在 updateQueue 中引入环状链表结构并完成入队逻辑

**路径:** `packages/react-reconciler/src/updateQueue.ts`

**修改内容:**
1. 为 `Update` 接口新增 `next` 指针，用于把多个 update 串联成链表节点
2. `createUpdate` 创建节点时补齐 `next: null` 初始化，确保节点结构完整
3. 重写 `enqueueUpdate`，将 `shared.pending` 从“单节点引用”升级为“环状链表尾节点引用”：
   - 空队列时：`update.next = update`，形成自环
   - 非空队列时：新节点插入到尾节点后、头节点前，保持环状结构
   - 最后统一将 `shared.pending` 指向新尾节点
4. 新增注释明确 `pending`/`next` 语义，便于后续 `processUpdateQueue` 按链表顺序消费更新

```diff
 export interface Update<State> {
   action: Action<State>;
+  next: Update<any> | null;
 }

 export const createUpdate = <State>(action: Action<State>): Update<State> => {
   return {
-    action
+    action,
+    next: null
   };
 };

 export const enqueueUpdate = <State>(
   updateQueue: UpdateQueue<State>,
   update: Update<State>
 ) => {
+  const pending = updateQueue.shared.pending;
+  if (pending === null) {
+    // pending = a -> a
+    update.next = update;
+  } else {
+    // pending = b -> a -> b
+    // c.next = b.next
+    update.next = pending.next;
+    // b.next = c
+    pending.next = update;
+  }
+  // pending 指向 update 环状链表的最后一个节点
+  // 尾节点.next 永远指向头节点
+  // pending = c -> a -> b -> c
   updateQueue.shared.pending = update;
 };
```

## 第四部分:个人 Q&A

### 1. 为什么 `enqueueUpdate` 这么实现就能形成环状链表？

核心点是两条约定始终成立：

1. `pending` 永远指向尾节点
2. 尾节点的 `next` 永远指向头节点

只要这两条不被破坏，链表天然就是环。

`enqueueUpdate` 每次插入时都在维护这两条约定：

- **空队列（第一次插入）**
  - `update.next = update`
  - `pending = update`
  - 结果是 `a -> a`，单节点自环

- **非空队列（后续插入）**
  - 先让新节点指向头：`update.next = pending.next`
  - 再让旧尾指向新节点：`pending.next = update`
  - 最后把 `pending` 移到新节点：`pending = update`
  - 等价于把新节点插到“尾和头之间”，环不会断

举例：

- 原来：`pending = b`，链表是 `b -> a -> b`
- 插入 `c` 后：`c -> a -> b -> c`

可以把它想成一圈人：

- `pending` 是队尾
- `pending.next` 是队头
- 新人总是站在“队尾和队头之间”
- 再把“队尾标记”移到新人

所以这圈人永远闭合，结构就一直是环状链表。
