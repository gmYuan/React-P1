# React Update 流程初探实现

## 第一部分：顶层鸟瞰

### 背景问题

在 React 开发过程中,mount(首次渲染)和 update(更新)是两个核心流程。本文实现 update 流程,需要解决以下核心问题:

- 如何区分 mount 流程和 update 流程?
- 如何在 update 流程中复用已存在的 Fiber 节点?
- 如何处理节点删除的情况?
- 如何标记需要更新的节点(HostText 内容更新)?

**核心挑战:**
- 需要在 beginWork 阶段判断能否复用 current fiber(通过比较 key 和 type)
- 需要实现 Fiber 节点的删除标记机制(deletions 数组)
- 需要在 completeWork 阶段处理 HostText 内容更新的标记
- 需要实现 useFiber 函数来复用旧的 Fiber 节点
- 需要在 FiberNode 中添加 deletions 字段来存储被删除的子节点

### 关键技术栈

| 技术 | 说明 |
|------|------|
| **双缓存机制** | current 树和 workInProgress 树互相切换,复用 Fiber 节点 |
| **Fiber 复用** | useFiber 通过 createWorkInProgress 复用已存在的 Fiber 节点 |
| **deletions 数组** | 存储需要删除的子节点,在 commit 阶段统一处理 |
| **ChildDeletion Flag** | 标记父节点有子节点需要删除 |
| **Update Flag** | 标记 HostText 内容发生变化,需要在 commit 阶段更新 DOM |
| **key 和 type 比较** | 判断节点能否复用的核心逻辑 |
| **work 标签** | 使用带标签的 break 语句控制复杂的条件分支流程 |

## 第三部分:主要知识点

### 1. update 流程与 mount 流程的区别

**本节课主要内容:**
第10课 初探 update 流程

**update 流程与 mount 流程的区别:**

**对于 beginWork:**
- 需要处理 ChildDeletion 的情况
- 需要处理节点移动的情况 (abc -> bca)

**对于 completeWork:**
- 需要处理 HostText 内容更新的情况
- 需要处理 HostComponent 属性变化的情况

**对于 commitWork:**
- 对于 ChildDeletion,需要遍历被删除的子树

**对于 useState:**
- 实现相对于 mountState 的 updateState

---

### 2. beginWork 流程

**本节课只处理单一节点,所以省去了「节点移动」的情况。我们需要处理:**
- singleElement
- singleTextNode

**处理流程为:**

1. **比较是否可以复用 current fiber**
   - a. 比较 key,如果 key 不同,不能复用
   - b. 比较 type,如果 type 不同,不能复用
   - c. 如果 key 与 type 都相同,则可复用

2. **不能复用,则创建新的(同 mount 流程),可以复用则复用旧的**

**注意:** 对于同一个 fiberNode,即使反复更新,current、wip 这两个 fiberNode 会重复使用

### 3. completeWork 流程

主要处理「标记 Update」的情况。本节课我们处理 HostText 内容更新的情况。

### 5. Fiber 复用的核心:useFiber 函数

**作用:** 复用已存在的 Fiber 节点,创建 workInProgress

**实现:**

```typescript
function useFiber(fiber: FiberNode, pendingProps: Props): FiberNode {
  const clone = createWorkInProgress(fiber, pendingProps);
  clone.index = 0;
  clone.sibling = null;
  return clone;
}
```

**关键点:**
- 调用 createWorkInProgress 创建或获取 alternate
- 重置 index 为 0
- 清空 sibling(因为这是单节点复用)
- 返回可复用的 clone

### 6. deletions 数组的作用

**为什么需要 deletions 数组?**

在 reconcile 阶段,如果发现某个子节点不能复用,需要删除它。但是此时只是标记删除,真正的删除操作在 commit 阶段进行。

**deletions 数组存储:**
- 所有需要删除的直接子节点
- 在 commit 阶段遍历 deletions,依次删除这些子树

**实现机制:**

```typescript
function deleteChild(returnFiber: FiberNode, childToDelete: FiberNode): void {
  if (!shouldTrackEffects) {
    return;
  }
  const deletions = returnFiber.deletions;
  if (deletions === null) {
    returnFiber.deletions = [childToDelete];
    returnFiber.flags |= ChildDeletion;
  } else {
    deletions.push(childToDelete);
  }
}
```

### 7. work 标签的使用

在 reconcileSingleElement 中使用了带标签的 break 语句:

```typescript
const key = element.key;

  // update
  if (currentFiber.key === key) {
    // key相同
```

### 8. Update 和 ChildDeletion 的区别

| Flag | 标记位置 | 作用 | 处理时机 |
|------|---------|------|----------|
| **Update** | 自身节点 | 标记自身需要更新(如 HostText 内容变化) | commit 阶段更新 DOM |
| **ChildDeletion** | 父节点 | 标记有子节点需要删除 | commit 阶段遍历 deletions 数组删除子树 |

**示例:**

```typescript
// Update: 标记在 wip 自身
if (oldText !== newText) {
  markUpdate(wip); // wip.flags |= Update
}

// ChildDeletion: 标记在父节点
returnFiber.flags |= ChildDeletion;
returnFiber.deletions = [childToDelete];
```

### 9. 单节点 reconcile 的完整流程

```
触发更新(setState)
  ↓
reconcileChildFibers 调用
  ↓
判断 newChild 类型
  ├─ object + REACT_ELEMENT_TYPE → reconcileSingleElement
  │   ↓
  │   currentFiber !== null?
  │   ├─ 是 → update 流程
  │   │   ├─ key 相同 && type 相同 → useFiber 复用
  │   │   └─ key 不同 || type 不同 → deleteChild + 创建新 fiber
  │   └─ 否 → mount 流程
  │       └─ createFiberFromElement
  │
  └─ string/number → reconcileSingleTextNode
      ↓
      currentFiber !== null?
      ├─ 是 → update 流程
      │   ├─ tag === HostText → useFiber 复用
      │   └─ tag !== HostText → deleteChild + 创建新 fiber
      └─ 否 → mount 流程
          └─ new FiberNode(HostText)
```
