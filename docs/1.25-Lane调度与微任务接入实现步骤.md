## 第二部分:实战步骤

### 步骤 1:新增同步任务队列，作为 SyncLane 的回调容器

**路径:** `packages/react-reconciler/src/syncTaskQueue.ts`

**修改内容:**
1. 新增 `syncQueue`，用于暂存同步任务回调
2. 新增 `scheduleSyncCallback`，负责把同步任务加入队列
3. 新增 `flushSyncCallback`，负责批量执行队列任务，并用 `isFlushingSyncQueue` 防止重复 flush

```diff
+ // 同步的任务队列
+ let syncQueue: ((...args: any) => void)[] | null = null;
+ let isFlushingSyncQueue = false;
+
+ // 调度同步的回调函数
+ export function scheduleSyncCallback(callback: (...args: any) => void) {
+   if (syncQueue === null) {
+     syncQueue = [callback];
+   }
+   syncQueue.push(callback);
+ }
+
+ // 遍历执行同步的回调函数
+ export function flushSyncCallback() {
+   if (!isFlushingSyncQueue && syncQueue) {
+     isFlushingSyncQueue = true;
+     try {
+       syncQueue.forEach((callback) => callback());
+     } finally {
+       isFlushingSyncQueue = false;
+       syncQueue = null;
+     }
+   }
+ }
```

### 步骤 2:在 hostConfig 中补充微任务调度能力

**路径:** `packages/react-dom/src/hostConfig.ts`

**修改内容:**
1. 新增 `scheduleMicroTask` 导出
2. 调度策略按运行环境降级：
   - 优先 `queueMicrotask`
   - 其次 `Promise.resolve().then(...)`
   - 最后降级到 `setTimeout`
3. 为 reconciler 的同步任务 flush 提供统一宿主层入口

```diff
+ export const scheduleMicroTask =
+   typeof queueMicrotask === 'function'
+     ? queueMicrotask
+     : typeof Promise === 'function'
+     ? (callback: (...args: any) => void) => Promise.resolve(null).then(callback)
+     : setTimeout;
```

### 步骤 3:补充 lane 选择规则，支持从 pendingLanes 中挑选最高优先级

**路径:** `packages/react-reconciler/src/fiberLanes.ts`

**修改内容:**
1. 新增 `getHighestPriorityLane`
2. 使用 `lanes & -lanes` 取最低位的 1，作为当前最高优先级 lane

```diff
+ // 获取 lanes 中优先级最高的 lane
+ export function getHighestPriorityLane(lanes: Lanes): Lane {
+   // 默认规则：数值越小，优先级越高
+   return lanes & -lanes;
+ }
```

### 步骤 4:改造 workLoop 的 schedule 入口，接入「选 lane + 微任务 flush」

**路径:** `packages/react-reconciler/src/workLoop.ts`

**修改内容:**
1. 新增导入：
   - lane 相关：`getHighestPriorityLane`、`NoLane`、`SyncLane`
   - 同步队列：`scheduleSyncCallback`、`flushSyncCallback`
   - 宿主微任务：`scheduleMicroTask`
2. `scheduleUpdateOnFiber` 不再直接 `renderRoot`，改为调用 `ensureRootIsScheduled`
3. 新增 `ensureRootIsScheduled`：
   - 先从 `root.pendingLanes` 中选 `updateLane`
   - 若为 `NoLane` 直接退出
   - 若为 `SyncLane`：把 `performSyncWorkOnRoot` 放入同步任务队列，并在微任务中 `flushSyncCallback`
4. 新增 `performSyncWorkOnRoot`，先二次确认 lane 是否仍为 `SyncLane`，否则重新调度；确认后进入 render 流程

```diff
- export function scheduleUpdateOnFiber(fiber: FiberNode, lane: Lane) {
-   const root = markUpdateFromFiberToRoot(fiber);
-   markRootUpdated(root, lane);
-   renderRoot(root);
- }
+ export function scheduleUpdateOnFiber(fiber: FiberNode, lane: Lane) {
+   const root = markUpdateFromFiberToRoot(fiber);
+   markRootUpdated(root, lane);
+   ensureRootIsScheduled(root);
+ }
+
+ function ensureRootIsScheduled(root: FiberRootNode) {
+   const updateLane = getHighestPriorityLane(root.pendingLanes);
+   if (updateLane === NoLane) return;
+   if (updateLane === SyncLane) {
+     scheduleSyncCallback(performSyncWorkOnRoot.bind(null, root));
+     scheduleMicroTask(flushSyncCallback);
+   }
+ }
+
+ function performSyncWorkOnRoot(root: FiberRootNode, lane: Lane) {
+   const nextLane = getHighestPriorityLane(root.pendingLanes);
+   if (nextLane !== SyncLane) {
+     ensureRootIsScheduled(root);
+     return;
+   }
+   prepareFreshStack(root);
+   // ... render / commit 流程
+ }
```

## 第四部分:个人 Q&A

### 1. 这批改动文件的主题是什么？为什么要改动这些文件？

这批改动的主题可以概括成一句话：

把“调度系统”真正启动起来，让 React 不再是“来一个更新立刻执行”，而是“先进入调度，再在微任务里统一处理”。

整体目标：

上一批改动主要是给 update 增加 lane 信息，并把 lane 记录到 root；这次是在此基础上补上真正的调度行为：触发更新后，不直接进入 render，而是先进入调度流程，选出要处理的 lane，再安排执行时机。

各文件改动目的如下：

1. `packages/react-reconciler/src/syncTaskQueue.ts`
   - 作用：提供同步任务队列，暂存需要执行的同步回调
   - 新增：`syncQueue`、`scheduleSyncCallback`、`flushSyncCallback`
   - 通俗理解：先把任务放进“待办箱”，而不是每次更新都立刻开工，便于批量执行

2. `packages/react-dom/src/hostConfig.ts`
   - 作用：提供统一的微任务调度能力
   - 新增：`scheduleMicroTask`，按环境能力降级（`queueMicrotask` -> `Promise.then` -> `setTimeout`）
   - 通俗理解：给 reconciler 一个“尽快但不打断当前调用栈”的执行入口，用来 flush 同步队列

3. `packages/react-reconciler/src/fiberLanes.ts`
   - 作用：补齐 lane 挑选规则
   - 新增：`getHighestPriorityLane`
   - 通俗理解：当 root 上积压了多个 lane 时，需要一个明确规则决定“先做谁”，这里用最低位 1 对应最高优先级

4. `packages/react-reconciler/src/workLoop.ts`
   - 作用：把 schedule 阶段真正接入主流程
   - 关键变化：
     - `scheduleUpdateOnFiber` 从“直接 render”改为“ensureRootIsScheduled”
     - 新增 `ensureRootIsScheduled`：选 lane，按优先级决定调度方式
     - `SyncLane` 路径：入同步队列 + 微任务 flush
     - 新增 `performSyncWorkOnRoot`：执行前再确认 lane，避免优先级变化导致执行错误
   - 通俗理解：这里是“总调度台”，负责决定什么时候、以什么节奏开始干活，而不是一触发更新就马上跑完整 render/commit

一句话总结：

这批改动把“有 lane 信息”升级成了“lane 真正参与调度”：

**记录更新 -> 选最高优先级 lane -> 放入同步任务队列 -> 微任务统一 flush 执行。**
