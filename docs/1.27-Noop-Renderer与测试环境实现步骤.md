### 步骤 3:实现 Noop 宿主配置，补齐节点创建、插入、更新、删除和微任务能力

**路径:** `packages/react-noop-renderer/src/hostConfig.ts`

**修改内容:**
1. 定义三类宿主节点结构：
   - `Container`（HostRoot）
   - `Instance`（HostComponent）
   - `TextInstance`（HostText）
2. 实现工厂与挂载逻辑：
   - `createInstance`
   - `createTextInstance`
   - `appendInitialChild`
   - `appendChildToContainer`
   - `insertChildToContainer`
3. 实现提交阶段能力：
   - `commitUpdate` 中分发 `HostText` 更新
   - `commitTextUpdate` 更新文本内容
   - `removeChild` 从容器树移除子节点
4. 导出 `scheduleMicroTask`，按 `queueMicrotask -> Promise.then -> setTimeout` 逐级降级，满足调度器对微任务的调用需求

**关键代码:**

```diff
+ // packages/react-noop-renderer/src/hostConfig.ts
+ export interface Container {
+   rootID: number;
+   children: (Instance | TextInstance)[];
+ }
+
+ export interface Instance {
+   id: number;
+   type: string;
+   children: (Instance | TextInstance)[];
+   parent: number;
+   props: Props;
+ }
+
+ export interface TextInstance {
+   text: string;
+   id: number;
+   parent: number;
+ }
```

```diff
+ export const createInstance = (type: string, props: Props): Instance => ({
+   id: instanceCounter++,
+   type,
+   children: [],
+   parent: -1,
+   props
+ });
+
+ export const createTextInstance = (content: string) => ({
+   text: content,
+   id: instanceCounter++,
+   parent: -1
+ });
+
+ export const appendInitialChild = (parent, child) => {
+   // 校验不能重复挂载到不同父节点
+   child.parent = 'rootID' in parent ? parent.rootID : parent.id;
+   parent.children.push(child);
+ };
```

```diff
+ export function commitUpdate(fiber: FiberNode) {
+   switch (fiber.tag) {
+     case HostText:
+       const text = fiber.memoizedProps?.content;
+       return commitTextUpdate(fiber.stateNode, text);
+   }
+ }
+
+ export const commitTextUpdate = (textInstance: TextInstance, content: string) => {
+   textInstance.text = content;
+ };
+
+ export const removeChild = (container: Container, child: Instance | TextInstance) => {
+   const index = container.children.indexOf(child);
+   container.children.splice(index, 1);
+ };
```

```diff
+ export const scheduleMicroTask =
+   typeof queueMicrotask === 'function'
+     ? queueMicrotask
+     : typeof Promise === 'function'
+     ? (callback: (...args: any) => void) => Promise.resolve(null).then(callback)
+     : setTimeout;
```

### 步骤 4:实现 `createRoot` 与树结构导出，支持把 Noop 树转回 ReactElement 形态

**路径:** `packages/react-noop-renderer/src/root.ts`

**修改内容:**
1. 在 `createRoot` 内创建 `Container`，并通过 `createContainer` 建立 FiberRoot
2. 暴露 `render`，内部调用 `updateContainer` 驱动 reconciler
3. 新增 `getChildren` 与 `getChildrenAsJSX`：
   - 支持读取当前 Noop 树
   - 支持把容器树转换为 ReactElement 结构（多子节点时包成 Fragment）
4. 在 `childToJSX` 中处理三类输入：
   - 文本节点（string/number）
   - 数组节点（含文本拼接与多节点返回）
   - `Instance` 节点（组装 `type + props + children`）

**关键代码:**

```diff
+ // packages/react-noop-renderer/src/root.ts
+ export function createRoot() {
+   const container: Container = {
+     rootID: idCounter++,
+     children: []
+   };
+   const root = createContainer(container);
+
+   return {
+     render(element: ReactElementType) {
+       return updateContainer(element, root);
+     },
+     getChildren() {
+       return getChildren(container);
+     },
+     getChildrenAsJSX() {
+       return getChildrenAsJSX(container);
+     }
+   };
+ }
```

```diff
+ function getChildrenAsJSX(root: Container) {
+   const children = childToJSX(getChildren(root));
+   if (Array.isArray(children)) {
+     return {
+       $$typeof: REACT_ELEMENT_TYPE,
+       type: REACT_FRAGMENT_TYPE,
+       key: null,
+       ref: null,
+       props: { children },
+       __mark: 'Ygm'
+     };
+   }
+   return children;
+ }
```

## 第四部分:个人 Q&A

### 1. 这批改动在做什么？为什么要新增/修改这些文件？

**核心目标：给 React 做一个"测试专用的假浏览器"**

之前一直在用 **react-dom** 来渲染 React 组件，它会把组件变成真实的 DOM 节点（`<div>`、`<span>` 这些），显示在浏览器页面上。

但是现在要做的事情是：**创建一个"假的渲染器"**，它不会真的操作浏览器 DOM，而是把渲染结果存成一个纯 JavaScript 对象，方便：
1. **写自动化测试**（不需要真的打开浏览器）
2. **调试查看 React 内部生成的树结构**（可以直接 `console.log` 看到完整的树）

这个"假渲染器"就叫 **react-noop-renderer**（noop 意思是"什么都不做"）。

---

**各个改动的具体作用：**

**改动 1：新建一个"假渲染器"包**
- 创建了 `packages/react-noop-renderer/` 文件夹
- 写了 `package.json` 告诉项目："这是一个新包，它依赖 reconciler（React 核心调度逻辑）"
- 就像你要开一家新店，先得去工商局注册一个营业执照

**改动 2：让项目能找到这个"假渲染器"**
- 修改 `vite.config.js`，添加了别名配置
- 把 `hostConfig`（宿主环境配置）从指向 `react-dom` 改成指向 `react-noop-renderer`
- React 的核心代码在工作时需要知道："我到底是在浏览器环境还是在测试环境？"
- 这个改动就像**换了一个"适配器"**：
  - 之前插的是"浏览器适配器" → 调用 `document.createElement` 创建真 DOM
  - 现在插的是"测试适配器" → 调用 `createInstance` 创建假对象

**改动 3：实现"假 DOM 节点"的数据结构和操作**
- 在 `hostConfig.ts` 里定义了三种"假节点"：
  ```javascript
  // 根容器（相当于真实环境的 <div id="root">）
  Container = { rootID: 0, children: [...] }
  
  // 组件节点（相当于 <div>、<span>）
  Instance = { id: 1, type: 'div', children: [...], props: {...} }
  
  // 文本节点（相当于 "hello world"）
  TextInstance = { id: 2, text: 'hello world' }
  ```
- 然后实现了一堆操作函数：`createInstance`、`appendInitialChild`、`commitTextUpdate`、`removeChild`
- React 核心不关心"怎么渲染"，它只关心"给我一套增删改查的接口"
- 所以要实现一套**假的 DOM 操作**：
  - 真实环境：调用 `div.appendChild(child)` → 浏览器会把 child 显示在页面上
  - 测试环境：调用 `parent.children.push(child)` → 只是把对象加到数组里，不会有任何视觉变化
- 就像玩"过家家"，用玩具锅铲炒菜，并不会真的做出饭来，但"炒菜的流程"是一样的

**改动 4：提供一个 `createRoot()` 入口**
- 在 `root.ts` 里实现了对外接口：
  ```javascript
  const root = createRoot();  // 创建一个假的根容器
  root.render(<App />);       // 渲染组件
  root.getChildren();         // 查看渲染后的假 DOM 树
  ```
- 就像你开了一家餐厅，得有一个"前台"接待客人：
  - 客人说"我要点菜" → 调用 `render()`
  - 客人说"我看看后厨在做什么" → 调用 `getChildren()`
- 还做了一个很巧妙的事：`getChildrenAsJSX()` 可以把假 DOM 树**反向转换回 JSX 格式**，方便在测试里断言：
  ```javascript
  expect(root.getChildrenAsJSX()).toEqual(<div>Hello</div>);
  ```

**改动 5：把 demo 从"真渲染"改成"假渲染"**
- 把导入从 `react-dom/client` 改成 `react-noop-renderer`
- 现在运行 demo 时：
  - 页面上**不会显示任何东西**（因为没有真的操作 DOM）
  - 但可以打开控制台，输入 `window.root.getChildren()` 查看渲染结果
- 就像你原来是在"实体店"卖东西，现在改成"仓库模拟"，不真的摆出来，但可以查库存清单

**改动 6：写一个自动化测试**
- 用 Jest 写了一个测试用例，验证"组件卸载时，父组件的清理函数先执行，子组件后执行"
- 有了假渲染器后，就可以写**不依赖浏览器的测试**：
  - 不用打开浏览器窗口
  - 不用等页面加载
  - 测试运行速度快 100 倍
- 而且可以精确验证 React 内部的行为（比如"卸载顺序"），这在真实浏览器里很难测

---

**一句话总结：**

这批改动就是在做一件事：**给 React 造了一个"沙盘"（假渲染器），让你可以在不打开浏览器的情况下，测试和调试 React 的渲染逻辑。**

就像：
- 飞行员训练用"模拟驾驶舱" → 不需要真飞机
- 现在给 React 做了一个"模拟浏览器" → 不需要真 DOM

这样做的好处：
1. **写测试更方便**（不依赖浏览器环境）
2. **调试更清晰**（可以直接 `console.log` 看树结构）
3. **运行更快**（没有真实 DOM 的性能开销）
