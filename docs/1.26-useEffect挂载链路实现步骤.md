**路径:** `packages/react/src/currentDispatcher.ts`

### 步骤 5:在 fiberHooks 中实现 useEffect 挂载与 effect 环状链表

**路径:** `packages/react-reconciler/src/fiberHooks.ts`

**修改内容:**
1. 新增 effect 相关类型：`Effect`、`EffectCallback`、`EffectDeps`、`FCUpdateQueue`
2. 调度器挂载路径新增 `useEffect: mountEffect`（mount/update dispatcher 均先接到 mount 实现）
3. 新增 `mountEffect`：
   - 为当前 hook 分配节点
   - 给 `currentlyRenderingFiber.flags` 打上 `PassiveEffect`
   - 通过 `pushEffect` 写入 effect 链表
4. 新增 `pushEffect`，在 `fiber.updateQueue` 上维护环状 effect 链表（`lastEffect` 尾插）
5. 新增 `createFCUpdateQueue`（当前代码命名为 `creactFCUpdateQueue`），初始化函数组件 updateQueue 并挂载 `lastEffect`
6. 调整 `updateState` 函数签名，显式返回 `[State, Dispatch<State>]`
7. 移除一处过时 TODO 注释，避免更新路径歧义

```diff
+ import { EffectTags, HookHasEffect, Passive } from './hookEffectTags';
+ import { PassiveEffect } from './fiberFlags';
+
+ export interface Effect {
+   tag: EffectTags;
+   create: EffectCallback | void;
+   destroy: EffectCallback | void;
+   deps: EffectDeps;
+   next: Effect | null;
+ }
+
+ export interface FCUpdateQueue<State> extends UpdateQueue<State> {
+   lastEffect: Effect | null;
+ }
+
+ const HooksDispatcherOnMount: Dispatcher = {
+   useState: mountState,
+   useEffect: mountEffect
+ };
+
+ function mountEffect(create: EffectCallback | void, deps: EffectDeps | void) {
+   const hook = mountWorkInProgressHook();
+   const nextDeps = deps == undefined ? null : deps;
+   (currentlyRenderingFiber as FiberNode).flags |= PassiveEffect;
+   hook.memoizedState = pushEffect(
+     Passive | HookHasEffect,
+     create,
+     undefined,
+     nextDeps
+   );
+ }
+
+ function pushEffect(
+   tag: EffectTags,
+   create: EffectCallback | void,
+   destroy: EffectCallback | void,
+   deps: EffectDeps
+ ): Effect {
+   const effect: Effect = {
+     tag,
+     create,
+     destroy,
+     deps,
+     next: null
+   };
+   const fiber = currentlyRenderingFiber as FiberNode;
+   const updateQueue = fiber.updateQueue as FCUpdateQueue<any>;
+   if (updateQueue === null) {
+     const newUpdateQueue = creactFCUpdateQueue();
+     fiber.updateQueue = newUpdateQueue;
+     effect.next = effect;
+     newUpdateQueue.lastEffect = effect;
+   } else {
+     const lastEffect = updateQueue.lastEffect;
+     if (lastEffect == null) {
+       effect.next = effect;
+       updateQueue.lastEffect = effect;
+     } else {
+       const firstEffect = lastEffect.next;
+       lastEffect.next = effect;
+       effect.next = firstEffect;
+       updateQueue.lastEffect = effect;
+     }
+   }
+   return effect;
+ }
+
+ function creactFCUpdateQueue<State>() {
+   const updateQueue = createUpdateQueue<State>() as FCUpdateQueue<State>;
+   updateQueue.lastEffect = null;
+   return updateQueue;
+ }
```

## 第三部分:主要知识点

### 1. 这批改动文件的主题是什么？

**一句话概括：给 React 增加 useEffect 的挂载能力，让函数组件可以执行副作用。**

更具体说，就是让 `useEffect(() => {}, [])` 这种代码能跑起来，并且把副作用信息正确地挂到 Fiber 节点上，为后续在 commit 阶段执行这些副作用做好准备。

---

### 2. 为什么要改动这些文件？

#### Effect 数据结构的设计

useEffect 需要保存的信息包括：
- `tag`：标记这是什么类型的 effect（Passive = useEffect）
- `create`：副作用函数本身
- `destroy`：清理函数（create 返回的函数）
- `deps`：依赖数组
- `next`：指向下一个 effect（形成环状链表）

**为什么需要环状链表？**

因为一个函数组件里可能有多个 useEffect，需要把它们串起来，方便后续统一遍历执行。

#### 三层 Flag 标记系统

改动涉及三个层级的标记：

**① Fiber 层标记（fiberFlags.ts）**
- 新增 `PassiveEffect`：标记这个 Fiber 节点本次更新有副作用
- 用途：commit 阶段可以快速筛选出"哪些 Fiber 需要执行 effect"

**② Effect Hook 层标记（hookEffectTags.ts）**
- `Passive`：标记这是 useEffect 对应的 effect
- `HookHasEffect`：标记这个 effect 本次需要执行（依赖变化了）

**③ 两者配合使用**
- Fiber 上的 `PassiveEffect` 像是"这个组件有副作用"的大门牌
- Effect 上的 `Passive | HookHasEffect` 像是"具体哪个副作用要执行"的详细清单

#### 按照数据流向理解改动文件

**① React 入口层改动**
- `currentDispatcher.ts`：给 Dispatcher 接口加 useEffect 类型定义
- `react/index.ts`：导出 useEffect 供用户调用

**通俗理解：** 就像开一家店，先要在菜单上加这道菜（类型定义），再把菜端给客人（导出）。

**② 标记系统改动**
- `hookEffectTags.ts`：定义 effect 的各种标签
- `fiberFlags.ts`：定义 Fiber 节点的副作用标记

**通俗理解：** 给副作用贴上不同颜色的标签，commit 阶段看标签就知道该干什么。

**③ 核心实现改动（fiberHooks.ts）**
- 新增 `Effect`、`FCUpdateQueue` 类型
- 实现 `mountEffect`：创建 effect 对象 + 打标记
- 实现 `pushEffect`：把 effect 插入环状链表
- 实现 `createFCUpdateQueue`：初始化函数组件的 updateQueue

**通俗理解：** 
- `mountEffect` 是"登记窗口"：你来登记副作用，我给你发号
- `pushEffect` 是"排队系统"：把你的号牌串到队伍里
- 环状链表是"循环队列"：最后一个的 next 指向第一个，方便从任意位置开始遍历

---

### 3. 用生活化比喻串起来

假设函数组件是一个"任务处理中心"：

1. **之前只能处理同步任务**（useState）：来了就立刻做
2. **现在要支持异步任务**（useEffect）：需要登记、排队、打标记

这批改动就是在搭建这个"异步任务管理系统"：

- **前台接待**（react/index.ts）：接收用户的 useEffect 调用
- **登记处**（mountEffect）：记录任务信息，给任务打标签
- **排队区**（pushEffect）：把任务加入环状队列
- **标识牌**（flags/tags）：贴在 Fiber 和 effect 上，告诉 commit 阶段"这里有活要干"

**关键点：现在只是"挂载"阶段，只负责收集和标记，真正执行副作用要在 commit 阶段！**

---

### 4. 核心知识点总结

**主题：** 实现 useEffect 的挂载链路（mount 阶段）

**目的：** 
1. 让用户可以调用 useEffect
2. 把副作用信息正确保存到 Fiber 的 updateQueue 中
3. 给 Fiber 打上 PassiveEffect 标记
4. 为 commit 阶段执行副作用铺好路

**环状链表的插入策略：**
```
初始状态：lastEffect -> null

插入第一个 effect：
effect1.next = effect1  // 自己指向自己
lastEffect = effect1

插入第二个 effect：
firstEffect = lastEffect.next  // effect1
lastEffect.next = effect2      // effect1 -> effect2
effect2.next = firstEffect     // effect2 -> effect1
lastEffect = effect2           // 更新尾指针

结果：effect2 -> effect1 -> effect2（环状）
```

**下一步需要做的：**
- 实现 updateEffect（更新时的依赖对比）
- 在 commit 阶段真正执行 create 和 destroy 回调
- 处理副作用的调度时机（微任务异步执行）
