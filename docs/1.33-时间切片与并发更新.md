### 步骤 1:扩展 FiberRootNode，新增调度回调相关字段，为并发调度提供状态存储

**路径:** `packages/react-reconciler/src/fiber.ts`

**修改内容:**
1. 新增 `CallbackNode` 类型导入（来自 `scheduler` 包），用于描述 Scheduler 返回的调度任务节点
2. `FiberRootNode` 类新增 `callbackNode` 字段，保存当前正在被 Scheduler 调度的回调任务节点，后续可用它判断"调度是否被更高优先级任务取代"，以及取消旧的调度

### 步骤 2:改造 workLoop，实现时间切片与并发渲染流程

**路径:** `packages/react-reconciler/src/workLoop.ts`

**修改内容:**

**(1) 新增导入与退出状态定义**
1. 从 `fiberLanes` 中新增导入 `laneToSchedulerPriority`，用于在调度时将 Lane 转换为 Scheduler 优先级
2. 新增 `unstable_shouldYield` 导入（来自 `scheduler` 包），用于在并发工作循环中判断当前时间切片是否用尽
3. 新增 render 阶段退出状态类型 `RootExitStatus`，以及两个状态常量：`RootIncomplete = 1`（render 被中断）、`RootComplete = 2`（render 执行完成）

**(2) `prepareFreshStack` 增加状态重置**
1. 初始化 workInProgress 之前，先重置 `root.finishedLane = NoLane`、`root.finishedWork = null`，避免上一次（可能被中断的）渲染残留的结果影响新的渲染

**(3) 改造 `ensureRootIsScheduled`，实现"调度复用 + 高优先级抢占"机制**
1. 读取 `root.callbackNode` 作为 `existingCallback`，记录当前已存在的调度任务
2. 没有待处理更新时（`maxPendingLane === NoLane`），取消已存在的调度任务（`unstable_cancelCallback`），并重置 `callbackNode`、`callbackPriority`，然后 return
3. 比较新的最高优先级 `curPriority` 与上次调度的 `prevPriority`（即 `root.callbackPriority`）：相同优先级的更新直接 return，复用已有调度，不重复调度
4. 优先级不同（代表更高优先级的更新插入），先取消之前已存在的调度任务
5. 同步优先级分支：`performSyncWorkOnRoot` 的绑定参数去掉了 `lane`（改为函数内部自行获取最高优先级 lane）
6. 实现其他优先级（并发）分支：通过 `laneToSchedulerPriority` 将 Lane 转换为 Scheduler 优先级，再调用 `scheduleCallback(schedulerPriority, performConcurrentWorkOnRoot.bind(null, root))` 用宏任务调度并发渲染，并保存返回的 `newCallbackNode`
7. 调度完成后，更新 `root.callbackNode` 和 `root.callbackPriority`，记录本次调度的任务节点和优先级

**(4) 新增 `performConcurrentWorkOnRoot`，并发更新的入口函数**
1. 调度开始前先执行 `flushPassiveEffects` 保证所有 useEffect 回调执行完毕——因为 useEffect 回调可能触发更高优先级的更新；如果执行后 `root.callbackNode` 发生了变化，说明有更高优先级任务插入，直接 return null 放弃本次任务
2. 获取当前最高优先级 `updateLane`，若为 `NoLane` 直接 return null
3. 计算 `needSync`：当 `updateLane === SyncLane` 或 Scheduler 传入 `didTimeout`（任务已过期）时，本次渲染退化为同步、不可中断
4. 调用 `renderRoot(root, updateLane, !needSync)` 执行 render 阶段，根据返回的退出状态分别处理：
   - `RootIncomplete`（中断）：若 `root.callbackNode` 已变化，代表有更高优先级任务插入，return null；否则返回 `performConcurrentWorkOnRoot.bind(null, root)`，利用 Scheduler 的"连续回调"机制在下一个时间切片继续执行
   - `RootComplete`（完成）：设置 `root.finishedWork`、`root.finishedLane`，重置 `wipRootRenderLane`，进入 `commitRoot` 提交阶段
5. render 结束后调用 `ensureRootIsScheduled(root)` 重新调度剩余更新

**(5) 改造 `performSyncWorkOnRoot`，render 逻辑抽离**
1. 函数签名移除 `lane` 参数，改为内部通过 `getHighestPriorityLane(root.pendingLanes)` 获取
2. 原本内联的 render 阶段逻辑（初始化、workLoop 循环、错误处理）抽离为公共的 `renderRoot` 函数，此处改为调用 `renderRoot(root, nextLane, false)`（同步、不可中断）
3. 根据返回的退出状态处理：`RootComplete` 时设置 `finishedWork`、`finishedLane` 并进入 `commitRoot`；其他状态在 DEV 环境下报错"还未实现的同步更新结束状态"

**(6) 新增 `renderRoot`，同步/并发共用的 render 阶段入口**
1. 接收 `shouldTimeSlice` 参数，决定走时间切片（并发）还是同步流程
2. 仅当 `wipRootRenderLane !== lane` 时才调用 `prepareFreshStack` 初始化——中断后恢复执行同一优先级的渲染时，复用已有的 workInProgress，从中断处继续，这是时间切片"可恢复"的关键
3. 工作循环根据 `shouldTimeSlice` 分流：`workLoopConcurrent()`（可中断）或 `workLoopSync()`（不可中断）
4. 循环结束后根据 `workInProgress` 状态返回退出状态：
   - 时间切片模式下 `workInProgress !== null`，说明被中断，返回 `RootIncomplete`
   - 同步模式下 `workInProgress` 不为 null 属于异常，DEV 环境下报错
   - 其余情况返回 `RootComplete`
5. 渲染完成后不再直接调用 `commitRoot`，commit 时机交由调用方（`performSyncWorkOnRoot` / `performConcurrentWorkOnRoot`）根据退出状态决定

**(7) 工作循环拆分为同步/并发两个版本**
1. 原 `workLoop` 重命名为 `workLoopSync`，逻辑不变：循环执行 `performUnitOfWork` 直到 `workInProgress` 为 null
2. 新增 `workLoopConcurrent`，循环条件额外加入 `!unstable_shouldYield`：当 Scheduler 判断当前时间切片用尽时跳出循环，让出主线程，实现时间切片

+  root: FiberRootNode,
+  didTimeout?: boolean
+): any {
+  // 由于 useEffect 的回调函数可能触发更高优先级的更新
+  // 在调度之前需要保证 useEffect 回调已全部执行完
+  const curCallback = root.callbackNode;
+  const didFlushPassiveEffect = flushPassiveEffects(root.pendingPassiveEffects);
+  if (didFlushPassiveEffect) {
+    // 若 useEffect 回调执行完之后，有更高优先级的更新插入了
+    if (root.callbackNode !== curCallback) {
+      return null;
+    }
+  }
+
+  const updateLane = getHighestPriorityLane(root.pendingLanes);
+  const curCallbackNode = root.callbackNode;
+
+  if (updateLane === NoLane) return null;
+
+  const needSync = updateLane === SyncLane || didTimeout;
+  // render 阶段
+  const exitStatus = renderRoot(root, updateLane, !needSync);
+
+  // render 阶段结束后，进入 commit 阶段
+  ensureRootIsScheduled(root);
+
+  if (exitStatus === RootIncomplete) {
+    // 执行中断

+      return null;
+    }
